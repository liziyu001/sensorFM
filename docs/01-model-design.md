# 01 · SensorFM 模型解剖

> 目标：把论文里的模型拆成"一张张量形状图 + 几个可以单独理解的设计决策"。
> 读者背景假设：会 FFN / RNN / Transformer / UNet，软件工程和统计基础扎实，但没做过时间序列基础模型。
> 标记说明：✅ = 论文明确写了；❓ = 论文没写清楚，需要读 LSM-2 或自己定。

---

## 0. 一句话心智模型

> **把一天的可穿戴数据当成一张 1440×34 的"灰度图"，用 ViT 的 MAE 方式随机挖洞再补全；区别是这张图天生就有很多洞，模型要学会区分"本来就缺的洞"和"我故意挖的洞"，只对后者负责。**

这句话里的每个词都对应一个设计决策，下面逐个拆。

---

## 1. 输入：一天是什么形状

✅ 一个样本 = **24 小时 × 34 个分钟级特征**。

```
X ∈ R^{1440 × 34}
     │       └── 34 个通道：HR/HRV 13、SpO2 3、睡眠 4、运动 10、皮肤 4
     └── 1440 分钟
```

关键点：**输入不是原始波形**，而是设备端已经算好的分钟级聚合量（均值、标准差、计数、占比等）。论文明确说原始数据不保留，原因是功耗和存储。

这带来两个后果：

1. 模型看到的是"低分辨率"的生理/行为摘要，不是 beat-to-beat 的细节。
2. 这些特征在不同设备上的定义可能不同，跨设备迁移会有问题（论文自己也承认）。

✅ 预处理：
- 全局 z-score（用预训练集的 mean/std），裁剪到 [-5, 5]。
- 生理范围过滤：EDA 0–60 S、皮温 0–41℃、SpO2 <70% 置为缺失、>100% 截断、RMSSD/SDNN 上限 125 ms。
- off-wrist 数据丢弃。
- 滑动窗口步长 8–24 分钟随机；丢弃缺失 >80% 的窗口。

## 2. Token 化：1440×34 怎么变成 2448 个 token

✅ patch 大小 = **[20 分钟, 1 个通道]**。

```
X: [1440, 34]
  │  按时间切成 1440/20 = 72 段；每段保留 34 个通道
  ▼
patches: [72, 34, 20]
  │  每个 patch 是一个 20 维向量（20 个分钟值）
  ▼
tokens: 72 × 34 = 2448 个 token
```

**为什么是 20×1，而不是 20×5 或 60×34？**

- **不混合通道**：34 个通道的单位和含义完全不同（bpm、ms、℃、S、步/分、秒）。如果把它们塞进同一个 patch，线性投影会把不同量纲混在一起，模型还得先学会"这是哪个通道"。1 个通道一个 token，通道身份由位置编码承担，干净。
- **20 分钟**：这是一个折中。太短 → token 太多、注意力成本高；太长 → 丢掉分钟级动态（比如运动峰、睡眠阶段切换）。论文没有给消融，20 是经验选择。
- **token 数 2448**：这是理解算力的关键。对 110M 参数的模型来说，2448 是一个**很长**的序列；注意力不是免费的。

**token 的形状**：

```
token[k, c] = X[k*20 : (k+1)*20, c] ∈ R^{20}
k ∈ [0, 72), c ∈ [0, 34)
```

✅ 每个 token 通过一个线性层投影到模型维度 d：

```
e[k, c] = W_in · token[k, c] + b_in,   W_in ∈ R^{d×20}
```

B 模型 d=768。

❓ **部分缺失的 token 怎么处理**：论文说"用 mask token 替换有缺失观测的 patch"，但一个 20 分钟的 patch 可能只缺 3 分钟。是"缺一分钟就整个 token 置为 mask"，还是"保留部分观测、在注意力里遮掉缺失的分钟"？论文没有细说。第一版实现可以先用"整 token 缺失"的简化（见 `02-code-design.md`）。

## 3. 位置编码：模型怎么知道"这是哪个通道、几点钟"

✅ 2D 加性位置编码：

```
PE[k, c] = concat( E_c , P_k )  ∈ R^d
             │       │
             │       └── 时间维：72 个 patch 位置的 1D 正弦编码（d/2 维）
             └── 通道维：34 个通道的可学习 embedding（d/2 维）
```

注意这里的"2D"不是图像的 (x, y)，而是 **(时间 patch 索引, 通道索引)**。

✅ 时间维里还留了 **8 维**给循环日历特征：

```
minute-of-hour  → sin, cos   (2 维)
hour-of-day     → sin, cos   (2 维)
day-of-week     → sin, cos   (2 维)
day-of-year     → sin, cos   (2 维)
```

这 8 维让模型知道"这是凌晨 3 点"还是"下午 3 点"，而不只是"第 45 个 patch"。

**为什么通道 embedding 要可学习**：通道的语义（HR vs EDA）不是位置关系，没法用正弦编码；让模型自己学一个 34×d/2 的表更直接。

❓ 论文说"additive positional encodings"，但同时说"half of the encoding dimensions ... feature ... half ... temporal"。最自然的实现是：构造一个 d 维向量，前 d/2 维放通道 embedding，后 d/2 维放时间编码，然后**加到** token embedding 上。也可能是两半各自加到不同的维度子空间。第一版按"concat 后相加"实现即可。

## 4. 编码器：标准 ViT，但只对"看得见"的 token 做注意力

✅ ViT-1D encoder，pre-LN Transformer block：

```
for each layer:
    x = x + MHSA(LN(x))
    x = x + MLP(LN(x))
```

B 模型配置：

| 参数 | 值 |
|---|---|
| hidden size d | 768 |
| layers | 12 |
| heads | 12 |
| MLP dim | 3072 |
| 参数量（encoder） | ~85M |

**和标准 ViT 的区别**：

1. **1D token 序列**，不是 2D 图像 patch。
2. **patch 是 20×1**，不是正方形。
3. **mask 是核心输入**，不是可选的数据增强。

✅ MAE 式设计：编码器只处理**未被 mask 的 token**。论文里的 AIM 还提到"two stage token masking, leveraging token dropout and attention masking"——也就是除了直接丢掉 token，还可能保留 token 但在注意力里屏蔽它。

❓ **具体是哪种**：标准 MAE 是"编码器只吃 visible tokens，解码器再补 mask token"。AIM 为了处理 inherited missingness，可能改成"编码器吃全部 token，但用 attention mask 让缺失 token 不参与"。两种实现的选择会影响：
- 计算量（visible-only 更省，但 batch 内长度不固定，难并行）；
- 实现复杂度（all-with-mask 形状固定，好写）；
- 语义（inherited missing 是否也进入编码器）。

第一版建议用 **all-with-attention-mask**：形状固定 `[B, 2448, d]`，容易调试；等理解透了再试 visible-only 的稀疏实现。

## 5. 解码器：把洞补回来

✅ 解码器也是 ViT-1D，但更小：

| 参数 | 值 |
|---|---|
| hidden size | 512 |
| layers | 8 |
| heads | 16 |
| MLP dim | 2048 |
| 参数量（decoder） | ~25M |

流程：

```
encoder 输出 h: [B, 2448, d]
  │  线性投影到 d_dec=512
  ▼
z: [B, 2448, 512]
  │  在被 mask 的位置替换成可学习的 mask token
  │  （如果编码器已经吃过 mask token，这里可能不需要再替换）
  ▼
decoder（8 层）→ [B, 2448, 512]
  │  线性投影到 20 维
  ▼
X_hat: [B, 2448, 20]  → unpatchify → [B, 1440, 34]
```

**为什么解码器比编码器小**：MAE 的经典设计。编码器负责学表征（下游要用），解码器只负责重建（预训练完就丢掉）。所以解码器可以轻，省算力。

**和 UNet 的区别**：UNet 有 skip connection，把高分辨率特征直接送到解码器；MAE 没有 skip，mask 位置的信息只能从上下文推断。这是故意的——逼模型学语义，而不是抄近路。

## 6. AIM：全文最核心的设计

### 6.1 问题

可穿戴数据天生碎片化，缺失有四种典型来源：

1. **设备没电 / 没戴**：连续几小时缺失。
2. **传感器不支持**：某些设备没有 EDA/皮温。
3. **信号质量差**：运动伪影、PPG 接触不良。
4. **设备模式切换**：省电模式下降采样。

标准做法有两种，都不好：

- **插补**（mean/linear/NN）：引入偏差，尤其是连续块缺失时，线性插补会造出不存在的趋势。
- **丢弃**：浪费大量数据，而且丢弃本身是有偏的（缺数据的人往往就是设备使用少的人）。

### 6.2 AIM 的做法

✅ **把"真实缺失"和"人工掩码"合并成同一个 mask**：

```
M_inherited  : 数据本身缺失的位置（1 = 缺）
M_artificial : 训练时故意挖的洞
M_full       = M_inherited ∪ M_artificial
```

✅ **损失只在"人工挖的洞、且原本有观测"的位置计算**：

```
L = MSE( X_hat , X )  on  M_artificial ∧ ¬M_inherited
```

这句话是全文最容易被忽略、但最重要的一句。它的含义是：

- 对**真实缺失**的位置，模型不被惩罚——因为那些位置的 ground truth 本来就不存在。
- 对**人工挖的洞**，模型必须从上下文补出来——这是学习信号。
- 模型因此学会把"缺失"本身当成一种输入特征（"这个通道现在没有数据"），而不是一个需要抹平的噪声。

### 6.3 人工掩码的三种模式

✅ 论文的混合策略：

| 模式 | 比例 | 模拟的现实 |
|---|---|---|
| 随机 patch | 80% | 随机掉点、信号噪声 |
| 时间块 | 50% | 摘表、没电（连续几小时） |
| 模态块 | 50% | 传感器不支持/掉线（整个通道） |

❓ 这里的"50%"是指"掩掉 50% 的 token/时间/通道"，还是"50% 的样本用这种模式"？论文的表述是 "randomly applies one of the following masks: 80% random patch masking, 50% temporal block masking, and 50% modality block masking"，更像是**每个样本随机选一种模式，比例是掩码比例**。Table ED.5 又说验证损失是三种模式的复合，说明验证时三种都测。第一版可以按"每样本选一种模式"实现，并把这个选择做成配置。

### 6.4 为什么这招有效（直觉）

- **缺失不是随机的**：设备没电往往发生在旅行/生病/忘戴的时候；传感器不支持与设备型号相关。这些都与健康状态/行为相关。插补会把这个信号抹掉，AIM 会保留它。
- **训练/推理一致**：真实部署时数据一定有缺失，AIM 让训练分布和部署分布一致。
- **免费的数据增强**：同一份数据可以用不同的 mask 模式反复训练。

### 6.5 AIM vs 标准 MAE

| | 标准 MAE | AIM |
|---|---|---|
| 缺失来源 | 只有人工 mask | 人工 mask ∪ 真实缺失 |
| 损失位置 | 所有人工 mask | 人工 mask 且原本有观测 |
| 缺失 token | 不存在（输入是完整的） | 作为 mask token 输入 |
| 推理 | 只能补人工挖的洞 | 可以补真实缺失、可以外推 |

## 7. 损失

✅ 预训练：MSE，只算在"人工掩码且原本有观测"的位置。

```
L = (1/|M|) Σ_{(k,c) ∈ M} || X_hat[k,c] - X[k,c] ||²
M = M_artificial ∧ ¬M_inherited
```

目标值是 z-score 后的值，所以 MSE 是无量纲的，跨通道可比。

❓ 归一化是按元素平均还是按 token 平均？论文没写。第一版按元素平均（`sum / mask.sum()`）。

✅ 优化器：AdamW，wd 1e-4，cosine，lr 5e-4，5% warmup，batch 4096，最多 1M step。

## 8. 下游：冻结编码器 + 线性探针

✅ 这是评估"表征好不好"的标准协议：

```
每个人的所有天、所有 token 的 embedding
  │  mean + std（按维度）
  ▼
person vector: [2d]
  │  PCA → 50 维
  ▼
[可选] concat 人口学特征（年龄、性别、BMI、种族）
  │
  ▼
逻辑回归 / 线性回归
  │  5 折交叉验证（person-independent）
  ▼
ROC-AUC / Pearson / F1 / MAE
```

**为什么用线性探针**：如果表征真的好，简单的线性头就够；如果必须上复杂模型才能工作，说明表征本身没学到东西。这是一个**保守**的评估。

**为什么 PCA-50**：下游标签少（几百到几千人），embedding 维度高（768），直接线性头会过拟合。PCA-50 是把方差压到与标签量级匹配。

**这个协议证明了什么、没证明什么**：
- 证明：embedding 里线性可分的健康信息比手工特征多。
- 没证明：模型能替代临床诊断；也没证明换一个非线性头不会更好。

## 9. 生成：插补、外推、日指标恢复

✅ 三种生成任务：

| 任务 | 掩码方式 | 目的 |
|---|---|---|
| Random Imputation | 随机掩 80% token | 通用缺失 |
| Temporal Interpolation | 中间连续 10/30/60 分钟 | 摘表、没电 |
| Temporal Extrapolation | 末尾连续 10/30/60 分钟 | 预测未来 |
| Signal Imputation | 整通道 2/6/12/26 个 | 设备不支持 |

✅ 日指标恢复：人为抹掉连续 60 分钟，重建后重算日聚合（步数、睡眠阶段分钟、运动分钟、SpO2 分钟、皮温分钟），与未抹除的 ground truth 比。

论文结果：步数 99.7%、深睡 99.9%、轻度运动 99.2%。

## 10. 模型规模与算力

✅ 四个规模：

| 变体 | hidden | layers | heads | MLP | decoder | 总参数 |
|---|---|---|---|---|---|---|
| XXS | 64 | 2 | 1 | 256 | 48/1层 | 138,740 |
| XS | 128 | 4 | 2 | 512 | 96/1层 | 933,204 |
| S | 256 | 8 | 4 | 1024 | 192/2层 | 7,290,068 |
| B | 768 | 12 | 12 | 3072 | 512/8层 | 110,763,412 |

**算力直觉**（B 模型，单样本）：

- token 数 N = 2448。
- 注意力：N² × d ≈ 4.6×10^9 MAC/层；MLP：N × d × 4d ≈ 5.8×10^9 MAC/层。两者量级相当。
- 单样本前向约 5×10^11 FLOPs，反向约 3 倍 → 约 1.5×10^12 FLOPs。
- 1M step × batch 4096 ≈ 6.6×10^21 FLOPs。

**关键结论**：模型只有 110M 参数，但序列很长，所以**注意力占比高、数据吞吐是瓶颈**。这和 LLM 的"参数大、序列短"正好相反。工程上要重点优化数据管线，而不是模型并行。

## 11. 哪些是创新，哪些是标准件

| 组件 | 来源 | 是否创新 |
|---|---|---|
| ViT-1D | ViT | 标准 |
| MAE 掩码重建 | MAE | 标准 |
| Transformer block | Transformer | 标准 |
| 2D 位置编码 | ViT / 时间序列 | 标准组合 |
| **20×1 patch、按通道切 token** | 本文 | **设计选择，非新算法** |
| **AIM（缺失即信号）** | LSM-2 | **本文的核心继承** |
| 冻结编码器 + 线性探针 | 表征学习 | 标准 |
| 30K agent 实验 | 本文 | 工程方法，非科学发现 |
| 1 万亿分钟数据 | 本文 | 规模创新 |

**给老板的一句话**：架构上没有新算法，真正的差异是"数据规模 + 缺失建模 + 评估协议"。这也是为什么它难以复现——护城河是数据。
